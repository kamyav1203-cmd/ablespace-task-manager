2. About AbleSpace

AbleSpace is a purpose-built caseload management and collaboration workspace designed specifically for therapists, special educators, and speech-language pathologists (SLPs). In clinical and educational therapy settings, professionals struggle with highly fragmented task flows, keeping track of multi-student sessions, handling varying priority caseload directives, and documenting progress milestones.

This application addresses this problem by providing a cohesive workspace to track tasks, organize projects, assign workloads, and customize preferences. By organizing the daily caseload operations into a unified workspace, the app helps therapists focus on delivering quality care rather than managing administrative overhead.

As a development project, AbleSpace demonstrates end-to-end full-stack software development. It ties a React-based Next.js interface to a NestJS database api, incorporating rich client-side states, dynamic route compilation, relational database models, and an automated, stateless deployment pipeline.

3. What I Built

I built the entire full-stack task manager application, implementing the visual interface, backend infrastructure, database relations, and deployment scripting. The scope of implementation covers the following key areas:

Application Interface & UX

Designed a high-contrast theme layout featuring collapsible tables, task cards, animated sliding drawers, context dropdowns, and clean status indicators.

Caseload & Workspace Logic

Developed reactive list filtering, an interactive search engine, dynamic column visibilities, and dual-layout modes (List & Kanban Board).

Form Validations & Safety

Created modal input forms for adding projects and tasks. Integrated client-side validations and NestJS class-validators to enforce clean data boundaries.

Relational Database & Sync

Modeled TypeORM relationships (One-to-Many, Many-to-One) between Users, Projects, and Tasks with database autoseeding on startup.

  • Backend REST API: Engineered NestJS controllers, services, and modules to expose clean CRUD endpoints for caseload entities.
  • Adaptive Database Hot-Swapping: Integrated conditional database drivers using Wasm-based in-memory SQLite on Vercel to bypass read-only filesystem limits, while maintaining file-based SQLite locally.
  • Persistent Customizations: Created a theme toggle and custom color modes (Amber, Blue, Pink) utilizing React Context and localStorage synchronization.

4. Application Walkthrough

The following screens demonstrate the visual interface, actual user flows, and backend-connected functionalities of the running application.

Screenshot 1 — Unified Caseload Tasks Workspace

What you're seeing
The main tasks dashboard for the logged-in therapist (Dexter). Tasks are grouped by their clinical execution status: To Do, Doing, Completed, and On Hold.
What the user can do
Therapists can search for tasks, filter them dynamically, collapse/expand status categories, view priority weights, identify assignees, and add new tasks directly to each list.
What I implemented
Developed the UI using Tailwind CSS, implemented status-based sorting logic, designed the search filter algorithm, and integrated initials-based round avatar components for the assignees.
How it works
When the page loads, a React useEffect triggers an API call to the NestJS /api/tasks endpoint. The backend queries the SQLite database, returning a structured JSON list of tasks, which the frontend sorts and binds to the UI state.
Why it matters
This view provides therapists with an immediate summary of their daily workload, reducing cognitive load and helping prioritize urgent care items.

Screenshot 2 — Interactive Layout & Column Customizer

What you're seeing
The workspace layout customizer dropdown overlaying the tasks dashboard.
What the user can do
Users can toggle the layout between "List" and "Board" views, and check/uncheck columns (Priority, Members, Due Date, Labels, Status) to instantly customize column visibility.
What I implemented
Designed the interactive customizer dropdown using React state variables, added click-away listeners to automatically dismiss the dropdown, and implemented dynamic CSS grid classes that adapt according to the checked column options.
How it works
The visibility state is managed via React Context. Changing checkbox options updates this context, causing the task rows to conditionally render columns depending on whether their respective state keys are truthy.
Why it matters
Therapists frequently work on varying devices (laptops, tablets). Allowing them to customize column visibility prevents UI overcrowding on smaller screens.

Screenshot 3 — Relational Project Workspaces

What you're seeing
The dedicated Projects view listing active projects, their priority badges, assigned leads, and due dates.
What the user can do
Therapists can search projects, filter items, add new projects, and view progress. Clicking a project navigates to its related tasks.
What I implemented
Created the projects table component, implemented search capability, built custom priority badge styling, and mapped project leads to their database user records.
How it works
The table fetches records from the NestJS /api/projects endpoint. TypeORM automatically resolves the relationship from Project to User, allowing the lead's name and initials avatar to display alongside the project details.
Why it matters
Therapy targets are rarely standalone tasks; they are organized under structured plans. Providing a dedicated projects layer enables high-level program tracking.

Screenshot 4 — Project Creation and Validation Form

What you're seeing
The "Create New Project" inline creation form, expanded at the top of the Projects view.
What the user can do
Users can input the new project's name, choose a priority (High/Medium/Low), assign a lead therapist from the populated team dropdown list, and set a due date using the date selector.
What I implemented
Built the form state controllers, handled submit events, implemented form cancellation, and added client-side validation to ensure project name cannot be empty.
How it works
On click of "Save Project", the frontend sends a POST request with the JSON payload to NestJS /api/projects. The backend uses class-validator ValidationPipes to sanitize and confirm the inputs. If valid, the backend saves the row in the SQLite database and returns the new project record, prompting the frontend to reload the list dynamically.
Why it matters
Enabling quick inline creation streamlines data entry, saving busy therapists from navigating multiple page redirections just to log a new initiative.

Screenshot 5 — Sidebar Profile Dropdown and Personalization Settings

What you're seeing
The profile context settings dropdown menu which expands from the therapist's profile in the sidebar.
What the user can do
Therapists can view their email, switch between Light and Dark themes, toggle primary accent color configurations (Amber, Blue, Pink), and log out of their session.
What I implemented
Created the profile dropdown layout, designed custom theme switcher items, integrated the theme selection with our state provider, and styled the overlay shadows.
How it works
Selecting a theme or color updates the theme state context. This context dynamically injects class names (like .dark or .accent-pink) into the document root, changing the CSS variable definitions. The choice is instantly written to localStorage, so the system remembers the user's preference on return.
Why it matters
A visually comfortable workspace is essential for clinical environments. Giving therapists full control over contrast, dark mode, and focus accents increases overall comfort.

7. Technical Implementation

The system is architected as a decoupled full-stack application using modern JavaScript web engineering patterns:

Frontend

Built with Next.js (App Router) and TypeScript. I styled the visual dashboard with Tailwind CSS, utilizing a custom-tailored dark default theme. Managed application preferences and settings globally using React Context Providers, syncing with LocalStorage to maintain user choices across sessions.

Backend

Developed with NestJS. Handled request parsing using validation pipes and DTOs. Exposed standard Rest API routes to perform basic operations on projects, tasks, and users.

Database

Configured TypeORM with a dynamically adaptive database driver. To circumvent the read-only filesystem limits of Vercel serverless platforms, I wrote configuration logic that switches between file-based better-sqlite3 locally and in-memory WebAssembly sql.js in cloud production, ensuring flawless database performance in any environment.

Development Practices

  • Component-based architecture: Highly modularized code splitting (Sidebar, Views, Dropdowns, Modals) for optimal reusability.
  • Strict Type Safety: Enforced end-to-end typing using TypeScript interfaces for both UI components and API entities.
  • Robust E2E Tests: Automated integration checks using Jest to verify endpoint security and data return formats.

9. Challenges & Problem Solving

Challenge: Read-only Serverless Cloud Filesystem Restrictions

Problem: SQLite is a file-based engine. When deploying the NestJS backend to Vercel, the platform's read-only filesystem caused the TypeORM database to crash immediately because it could not write database files to the server root.
Solution: I refactored the database configuration module. I hotswapped the database driver to use the WebAssembly-based sqljs engine inside cloud deployments, running the DB in-memory. I then updated vercel.json to bundle the necessary sql-wasm.wasm binaries so they load successfully at runtime, resolving the crash.

Challenge: Static Route Exclusions on Serverless Platforms

Problem: Next.js static exports crash when encountering dynamic routes like /projects/[id] because static compilers require predefined parameters at build time.
Solution: I configured the frontend's build profile and routing configuration to dynamically render the routes, letting Vercel's routing engine handle client-side parameters cleanly without crashing.
